## Problems

1. **`update --release` ignores pre-releases.** Command: `python3 .../factory_release.py update --release`. Happened: refused. Expected: install `v0.1.0-alpha.1` as the plan says. Message: `factory update: [no_releases] there is no published release yet (pre-releases are only used when named).` and `Fix: ask the owner to cut one, or name a pre-release: factory update v1.0.0-rc.1.` `./factory version` also says `Newest unknown`.
2. **Agent worktree without the factory fails half-silently and `--once` keeps polling.** Command: `./factory coding-agent taytu loop --once` before PR #10 merged. Happened: tracebacks, then it kept running. Expected: stop with one clear error. Messages: `FileNotFoundError: [Errno 2] No such file or directory: '.claude/factory.json'`; `python3: can't open file '/home/factory/code/factory-sandbox-agents/taytu/.claude/hooks/factory_env.py'`; `[taytu] nothing ready (every task is done, blocked or taken). Checking again every 1 min; Ctrl-C stops.` It also printed `(slot 1)` for a slot-2 agent.
3. **Untrusted workspace is only discovered after spending tokens.** Command: `./factory coding-agent taytu loop --once`. Happened: 9 replies, 303k tokens, nothing done. Expected: `doctor` or the loop says so first. Message: `Ignoring 20 permissions.allow entries from .claude/settings.json: this workspace has not been trusted. Run Claude Code interactively here once and accept the trust dialog, or set projects["/home/factory/code/factory-sandbox"].hasTrustDialogAccepted: true in /home/factory/.claude.json.` `./factory doctor` said "All the checks pass" at that time.
4. **Headless run cannot write files or run the project's test.** Command: same, after trust. Happened: `taytu` stopped asking for permission. Expected: write `tests/test_textkit.py` and run it without a prompt. Messages: `Claude requested permissions to write to /home/factory/code/factory-sandbox-agents/taytu/tests/test_textkit.py, but you haven't granted it yet.`; subagent: `Permission to use Write has been denied.` then `Permission to use Bash has been denied.`; earlier run: `This command requires approval` for `git fetch origin`, `python3 .claude/hooks/next_task.py --issue 2`, `printenv`. `permissions.defaultMode` is unset.

Happened: sub-manager posted `<!-- factory-review-claim manager=fasil sha=197a197... -->`, released it seconds later, wrote a `factory-manager-note`, no review, label or comment with a verdict. 9. **Default model changes between runs** (opus-5-5 then sonnet-5-5) while `doctor` reports "Claude Code default". Cannot be pinned from the project.

## The five things most worth fixing

1. **Give the headless loop the permissions it needs** (write and edit in the worktree, the project's test command, `git`, the factory hooks), or run `claude -p` with a permission mode the owner chooses. Without it no task can be built on a fresh machine (problem 4).
2. **Make `factory doctor` catch what will block the loop before any tokens are spent**: untrusted workspace, no write permission, missing factory files in the agent worktree (problems 2, 3, 4). It said "All the checks pass" while the loop could not work.
3. **Release claims when a run fails or its agent goes down, and keep the agent's report truthful** (problem 5), and make `issues release` / `issues setup` say what they did (problem 6).
4. **Fail fast and clearly when the agent worktree has no factory** instead of tracebacks and endless polling after `--once` (problem 2).
5. **Let `update --release` install a named pre-release** (or say so in the plan), and make `factory version` show it (problem 1).
