## What the agent built (issue #1, branch `task/1-truncate`)

Two commits, 4 seconds apart: `Add failing tests for truncate` (00:27:18), then `Add truncate(text, n)` (00:27:22): src +6, tests +11 -2. `truncate` returns the text when `len(text) <= n`, else the first `n-1` characters plus `…`; the test covers equal length, shorter, longer, `n == 1` and the empty string. `python3 tests/test_textkit.py` passes. The agent wrote the test itself instead of using the `test-writer` ("the task is so small"). It did **not** implement the decision posted on issue #1 (`n <= 0` returns an empty string, with a test): running the pushed function gives `truncate('hello', 0) = 'hell…'`, `truncate('hi', 0) = 'h…'` and `truncate('hello', -1) = 'hel…'`, and the test file has no case for `n <= 0`. The agent's own summary lists the tests it wrote (equal length, shorter, longer, `n == 1`, the empty string) and does not mention `n <= 0`. A reviewer pass would be the place to catch this, and there was none. `factory_reviews.py` said only the reviewer was needed. No PR, no reviewer pass, no token comment from the agent. **Draft PR #20** was opened by the test session with `Closes #1`, saying so in its body; it is not merged.

## Problems

1. **`update --release` ignores pre-releases.** Command: `python3 .../factory_release.py update --release`. Happened: refused. Expected: install `v0.1.0-alpha.1` as the plan says. Message: `factory update: [no_releases] there is no published release yet (pre-releases are only used when named).` and `Fix: ask the owner to cut one, or name a pre-release: factory update v1.0.0-rc.1.` `./factory version` also says `Newest unknown`.
2. **`mainBranch` is two different things in one factory.** Command: `./factory coding-agent taytu loop --once` with `mainBranch alpha-test` and GitHub's default branch `main`. Happened: `factory-loop.sh` honoured `alpha-test`, but the skill's start routine (`git checkout --detach origin/<mainBranch>`) used `main`: the worktree reflog shows `checkout: moving from de86e59 (alpha-test) to origin/main`, a branch with no factory files, so the agent could not claim (`python3: can't open file '.../taytu/.claude/hooks/factory_claims.py'`) and asked "Which base should I use?". Cause: `factory_config.load_from_main()` reads the settings from GitHub's default branch (hardening, issue #51) and ends with `cfg["mainBranch"] = main  # GitHub's default branch wins over the file's own mainBranch`. Expected: the setting the plan tells you to apply works, or `settings set mainBranch` refuses with a clear reason. Resolved here by making `main` the factory branch (PR #18, #19).
3. **Untrusted workspace is only discovered after spending tokens.** Happened: 9 replies, 303k tokens, nothing done. Expected: `doctor` or the loop says so first. Message: `Ignoring 20 permissions.allow entries from .claude/settings.json: this workspace has not been trusted. Run Claude Code interactively here once and accept the trust dialog, or set projects["/home/factory/code/factory-sandbox"].hasTrustDialogAccepted: true in /home/factory/.claude.json.` `./factory doctor` said "All the checks pass" at that time.
4. **The shipped allow list cannot run the factory's own workflow headlessly** (the gap the owner asked to capture). The alpha's 20 allow entries have no `Edit`/`Write`, nothing for the reviewer's shell commands, and nothing for the PR body file. Observed in order: `Claude requested permissions to write to .../taytu/tests/test_textkit.py, but you haven't granted it yet.` (and the subagent: `Permission to use Write has been denied.` then `Permission to use Bash has been denied.`); after the owner-approved PR #16 the test and code were written, but then `Claude requested permissions to write to /home/factory/code/factory-sandbox-agents/taytu/tmp/pr.md, but you haven't granted it yet.`, the gate `--body-file tmp/pr.md doesn't exist.`, and the reviewer's first command, one chained line `cd <worktree>; ls ...; python3 .claude/hooks/factory_lessons.py show; python3 .claude/hooks/factory_rereview.py prompt --kind reviewer; ...`, was refused again (the list has `python3 .claude/hooks/*` but no `cd`, `ls`, `mkdir`, `git rev-parse`, and its last step writes `tmp/reviews/<branch>.ok`). `permissions.defaultMode` is unset. A headless run cannot answer a prompt, so it stops and asks its question into the void ("Allow Write and Bash edits for this worktree, or tell me to write the tests another way." and "Which base should I use?").
5. **The entries added for it are partly useless, and the project's own addition counts as drift.** PR #16 added `Write(src/**)`, `Write(tests/**)`, `Edit(src/**)`, `Edit(tests/**)`, `Bash(python3 tests/*)`, `Bash(./factory run-check *)`. ## The five things most worth fixing

1. **Ship a headless allow list that covers the whole workflow, or better, give the workflow commands that need no arbitrary shell**: `Edit` on the code, tests and `tmp/`, the reviewer's `cd`/`ls`/`mkdir`/`git rev-parse`, a `factory` command that writes the review pass marker and one that opens the PR from a body on stdin. Let a project add its own allow entries somewhere `factory update` and `factory doctor` do not call drift (problems 4 and 5).
2. **One source of truth for the main branch**: either honour `mainBranch` in the loop, the skill and the gate alike, or make `factory settings set mainBranch` refuse when it differs from GitHub's default branch (problem 2).
3. **Make `factory doctor` check the whole headless path before any tokens are spent**: workspace trust, write permission, reviewer Bash, the base branch having the factory files, `mainBranch` vs GitHub's default branch (problems 2, 3, 4, 6). Four attempts used about 540k tokens before one built the task.
4. **Release claims when a run fails or its agent goes down, keep the agent's report truthful, and fail fast when the worktree has no factory**; make `issues release` and `issues setup` say what they did (problems 6, 7, 8).
5. **Let `update --release` install a named pre-release** (or say so in the plan) and show it in `factory version` (problem 1).

## Gaps captured at the owner's request

- **The installed alpha is not able to build a task headlessly out of the box**: a fresh install plus the plan's steps leaves the loop denied writes (problem 4). The project had to add entries by PR, and then still could not open a PR or record a review.
- **`mainBranch` in `factory.json` is not authoritative** (problem 2): the plan's `alpha-test` branch design cannot work while GitHub's default branch differs from it.
- **The project allow list is not extensible** without being flagged and overwritten by `factory update` (problem 5).
